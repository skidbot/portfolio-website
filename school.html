Coursework

Penetration test of OWASP Juice Shop

OWASP Juice Shop is a deliberately insecure web store built for security training. ZAP's automated scan flagged 16 types of alerts, then I attacked the app by hand through ZAP's proxy.

  • Logged in as the administrator, and used SQL injection to get into another customer's account without their password.
  • Reset a user's password by exploiting a weak security question.
  • Downloaded a confidential document from an exposed file directory.

Tools: OWASP ZAP, OWASP Juice Shop

Coursework, Secure Business Applications

Security review of a legacy e-commerce app

closedShop is a legacy e-commerce site built on a Perl codebase. Across five assignments I assessed it the way a security team would before trusting it with customer data.

  • Built a threat model of the application in OWASP Threat Dragon.
  • Did a systematic software review and created SSD diagrams.
  • Wrote a secure software design document.
  • Reviewed the code against the CIA triad, non-repudiation, the Gold Standard (authentication, authorization, audit), and design-pattern matrices.

Tools: OWASP Threat Dragon

Security+ hands-on labs

More than 20 labs and case projects from my Security+ coursework, based on the CompTIA Security+ textbook. Each one is written up with screenshots and my answers.

Home lab, March 2026

RAID 6 failure and recovery lab

A self-directed lab to test RAID 6's two-drive fault tolerance, built with mdadm from five 10 GB virtual disks on Ubuntu Server.

  • Failed one drive, then a second, and confirmed the data survived both.
  • Pulled disks while the array was running, then forced a collapsed array with out-of-date metadata back together.
  • Made the array survive reboots by saving the mdadm configuration, updating initramfs, and adding it to fstab.

Tools: Ubuntu Server, VirtualBox, mdadm

Coursework, Systems Analysis and Design, spring 2025

Class scheduling system for a training studio

I interviewed the owners of Stay Well Studios, a personal training business that scheduled classes by hand, and turned their needs into a 30-page software requirements specification and a working prototype in Caspio.

  • Role-based views for clients, trainers, and owners to book, configure, and track classes.
  • Use cases, user stories, a domain class model, and a data dictionary, revised as the prototype evolved.
  • Navigation and feedback designed around Nielsen's usability heuristics.

Tools: Caspio, UML, use cases and user stories, ERDs

Retail sales analysis for a new store
